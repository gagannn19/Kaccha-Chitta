# Level 5 : Interview & Revision Questions

<sub>Level 5 : Memory Management</sub>

## 🎯 Top interview questions

<details><summary><b>1. Logical vs physical address?</b></summary>

Logical (virtual) address is generated by the CPU / seen by the program. Physical address is the real location in RAM. The MMU translates logical to physical.

</details>
<details><summary><b>2. Internal vs external fragmentation?</b></summary>

Internal: wasted space inside an allocated block (block bigger than needed). External: enough total free memory exists but not in one continuous piece.

</details>
<details><summary><b>3. What is paging? Why is it used?</b></summary>

Dividing a process into fixed-size pages and RAM into same-size frames; any page can go to any frame. It removes external fragmentation and makes allocation simple.

</details>
<details><summary><b>4. What is a TLB?</b></summary>

Translation Lookaside Buffer: a small fast hardware cache storing recent page→frame translations, so most address translations skip the page table in RAM.

</details>
<details><summary><b>5. Paging vs segmentation?</b></summary>

Paging uses fixed-size blocks invisible to the programmer (internal fragmentation). Segmentation uses variable-size logical units like code, stack, data (external fragmentation).

</details>
<details><summary><b>6. What is virtual memory?</b></summary>

A technique that lets a process use more memory than physically available by keeping only needed pages in RAM and the rest on disk (swap), loaded on demand.

</details>
<details><summary><b>7. What is a page fault?</b></summary>

An interrupt raised when a process accesses a page not currently in RAM. The OS loads it from disk (replacing a page if needed), updates the page table and restarts the instruction.

</details>
<details><summary><b>8. What is thrashing? How to prevent it?</b></summary>

When the system spends more time swapping pages than executing, because processes don't have enough frames. Prevent with the working-set model, page-fault-frequency control, reducing multiprogramming, or adding RAM.

</details>
<details><summary><b>9. What is Belady's anomaly?</b></summary>

With FIFO, increasing the number of frames can increase page faults (e.g. 1 2 3 4 1 2 5 1 2 3 4 5: 9 faults with 3 frames, 10 with 4). LRU and Optimal don't suffer from it.

</details>
<details><summary><b>10. Which page replacement is best?</b></summary>

Optimal gives the fewest faults but needs future knowledge. LRU is the best practical approximation; real OSes use LRU approximations like the Clock (second-chance) algorithm.

</details>

## 🔁 Quick revision

1. Page size 4 KB, logical address 9000. Page number and offset?
2. Which fragmentation does paging remove?
3. Reference 1 2 3 1 4 2 with 3 frames, FIFO: how many faults?
4. Same string with LRU?
5. What is stored in a page table entry (basic)?

<details><summary>Answers</summary>

1. p = 9000 / 4096 = 2, d = 9000 − 8192 = 808
2. External
3. FIFO: 1F 2F 3F 1H 4F(out 1) 2H → **4 faults**
4. LRU: 1F 2F 3F 1H 4F(out 2) 2F(out 3) → **5 faults**
5. Frame number + bits like valid/invalid, dirty, protection

</details>
